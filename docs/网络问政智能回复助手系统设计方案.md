# 网络问政智能回复助手系统设计方案

> **版本说明**：本文档基于实际项目实现（GovMcpGateway + GovServiceMock 子模块）进行更新，反映真实的系统架构和数据定义，供后续 Agent 项目开发参考。

## 1. 系统概述

### 1.1 项目背景

12345政务服务热线是群众诉求表达的核心渠道，面临海量诉求人工处理效率低、跨部门协同难、民生热点预警滞后等痛点。本项目旨在构建一个智能回复助手，实现群众诉求的自动分类、智能回复与工单流转闭环，提升政务服务效率与群众满意度。

### 1.2 系统目标

- **智能优先**：基于历史案例、权责清单、部门办事清单、网络权威信息，对群众咨询类诉求实现高置信度自动回复。
- **人工兜底**：对无法自动回复的诉求自动创建工单，进入现有工单流转系统，由人工办理。
- **闭环迭代**：人工办结的优秀案例自动沉淀至知识库，持续优化系统回复效果。
- **安全合规**：全流程敏感信息脱敏、内容审核、权限管控，符合政务数据安全规范。

## 2. 系统总体架构

系统采用分层、模块化设计，自上而下分为四层：

```
┌─────────────────────────────────────────────────────────────┐
│                      交互层（群众端/政务端）                  │
├─────────────────────────────────────────────────────────────┤
│                    Agent层（LangChain/LangGraph）             │
│          （任务规划、工具调用、置信度评估、知识融合）          │
├─────────────────────────────────────────────────────────────┤
│               MCP协议转换层（Spring AI MCP Server）           │
│     （动态工具注册、Dubbo泛化调用、HTTP代理）                │
├─────────────────────────────────────────────────────────────┤
│                  政务微服务层（Dubbo服务集群）                │
│   （工单服务、权责清单服务、案例检索服务、部门知识库服务）     │
└─────────────────────────────────────────────────────────────┘
                        ▲
                        │
                ┌───────┴───────┐
                │  Nacos 注册/配置中心 │
                └───────────────┘
```

### 2.1 架构说明

本方案采用 **Spring AI MCP Server** 作为 MCP 协议转换层的核心实现，与传统设计相比，架构更加简洁：

| 层级 | 职责 | 技术实现 |
| :--- | :--- | :--- |
| **交互层** | 群众通过小程序/Web提交诉求，政务人员通过管理后台查看工单与统计 | 小程序/Web |
| **Agent层** | 系统的智能中枢，负责任务规划、调用MCP工具、评估回复置信度、融合多源知识 | LangChain/LangGraph |
| **MCP协议转换层** | 将Agent的MCP请求通过Dubbo泛化调用或HTTP转发到后端微服务 | Spring AI 1.1.2 MCP + Dubbo Generic |
| **政务微服务层** | 现有业务服务（工单系统、权责清单、案例检索等），通过Dubbo注册到Nacos | Spring Boot + Dubbo + Nacos |

### 2.2 核心设计思想

1. **动态工具注册**：工具定义存储在Nacos配置中心，Gateway启动时自动加载并注册为MCP工具，支持热更新。
2. **Dubbo泛化调用**：MCP Gateway 无需引入业务Jar包，通过 Dubbo Generic Service 实现纯动态调用。
3. **策略模式扩展**：通过 `ToolStrategy` 接口支持 LOCAL（本地脚本）、DUBBO（Dubbo调用）、REMOTE（HTTP调用）三种工具类型。

## 3. 模块详细设计

### 3.1 Agent层

#### 3.1.1 核心职责

- 接收用户诉求文本
- 调用 MCP 工具获取匹配部门、检索知识库、创建工单等
- 融合多源知识，生成回复候选
- 评估回复置信度，若≥阈值则直接返回，否则创建工单
- 维护对话状态（工单ID、处理进度等）

#### 3.1.2 工具调用流程

1. **工具发现**：Agent 从 MCP Server 获取可用工具列表（符合 MCP 规范）
2. **参数准备**：Agent 根据工具的 Input Schema 准备调用参数
3. **工具执行**：MCP Server 根据工具类型（Dubbo/HTTP/Local）调用对应的后端服务
4. **结果返回**：工具执行结果返回给 Agent，Agent 解析并生成回复

### 3.2 MCP协议转换层（Spring AI MCP Server）

#### 3.2.1 核心组件

| 组件 | 职责 | 实现类 |
| :--- | :--- | :--- |
| **DynamicToolRegistry** | 动态工具注册桥接器，实现 `ToolCallbackProvider` 接口，将 Nacos 配置的工具定义转换为 MCP 工具 | `com.gov.gateway.component.DynamicToolRegistry` |
| **ToolProperties** | 工具配置属性，支持 Nacos 热更新 | `com.gov.gateway.config.ToolProperties` |
| **ToolStrategyFactory** | 工具策略工厂，分发到具体的执行策略 | `com.gov.gateway.strategy.ToolStrategyFactory` |
| **DubboGenericStrategy** | Dubbo 泛化调用策略，实现纯动态 RPC 调用 | `com.gov.gateway.strategy.impl.DubboGenericStrategy` |

#### 3.2.2 工具配置示例

工具定义存储在 Nacos 配置中心（Data ID: `gov-service-mock-mcp.yml`）：

```yaml
agent:
  tools:
    - name: "create_gov_work_order"
      description: "创建政务工单。用户提交诉求后，AI Agent 调用此接口创建工单..."

      inputSchema: '{...}'
      metadata:
        interface: "com.gov.mock.service.WorkOrderService"
        method: "createWorkOrder"
        group: "gov-political"
        version: "1.0.0"
        paramTypes:
          - "java.util.Map"
        paramNames:
          - "orderData"
```

## 4. 数据模型与枚举定义

> **重要**：以下枚举定义需要前后端保持一致，作为数据传输的规范。

### 4.1 工单状态枚举

```java
public enum WorkOrderStatus {
    UNASSIGNED,   // 未分拨: AI生成后的初始状态
    ASSIGNED,     // 已分拨: 人工/系统分拨给职能部门
    ACCEPTED,     // 已受理: 职能部门确认接收
    REPLIED,      // 已回复: 部门处理完成并回复
    RATED         // 已评价: 用户提交评价，流程结束
}
```

### 4.2 工单操作枚举

```java
public enum WorkOrderAction {
    ASSIGN,   // 分拨: 将工单分拨给具体部门
    ACCEPT,   // 受理: 部门确认接收并开始处理
    REPLY     // 回复: 处理完成后回复用户
}
```

### 4.3 工单数据模型

```java
@Data
public class WorkOrder implements Serializable {
    private String id;                 // 工单唯一编号
    private WorkOrderStatus status;    // 状态

    private String userId;            // 提交人ID
    private String userPhone;          // 联系方式

    private String title;              // [AI生成] 标题
    private String content;             // [AI生成] 详细描述
    private String department;         // 责任部门
    private PoliticalElements elements; // [AI生成] 五大核心要素

    private String replyContent;       // [工作人员] 回复内容
    private String handler;            // [工作人员] 经办人
    private UserFeedback userFeedback; // [用户] 评价详情

    private String createTime;         // ISO-8601 时间
    private String updateTime;         // ISO-8601 时间
}
```

### 4.4 五大核心要素（PoliticalElements）

```java
@Data
public class PoliticalElements implements Serializable {
    private String time;           // 时间
    private String location;       // 地点
    private String event;          // 核心事件
    private String goal;           // 诉求目标
    private List<String> subjects; // 涉及主体 (支持多主体)
}
```

### 4.5 用户评价（UserFeedback）

```java
@Data
public class UserFeedback implements Serializable {
    private Integer timeliness;  // 受理时效 (1-5分)
    private Integer attitude;   // 办理态度 (1-5分)
    private Integer result;     // 处理结果 (1-5分)
    private String comment;     // 文字评价
}
```

### 4.6 MCP 工具定义

| 工具名称 | 描述 | 参数 | 返回值 |
| :--- | :--- | :--- | :--- |
| `create_gov_work_order` | 创建政务工单 | `orderData: {userId, userPhone, title, content, department, elements}` | `{orderId: string}` |
| `query_gov_work_order` | 查询工单详情 | `orderId: string` | `WorkOrder 对象` |

| `submit_work_order_feedback` | 提交用户评价 | `orderId, feedbackData: {timeliness, attitude, result, comment}` | `{success, message}` |

## 5. 业务流程示例

**场景**：群众通过小程序提交诉求："请问灵活就业人员如何缴纳社保？"

1. **诉求预处理**：Agent 对文本进行清洗、脱敏、要素提取
2. **工具调用**：Agent 并行调用多个 MCP 工具获取知识库信息
3. **知识融合**：去重、排序、摘要，形成上下文
4. **回复生成**：LLM 生成回复，包含参保条件、所需材料、办理渠道
5. **置信度评估**：评估服务打分为 0.95
6. **直接回复**：Agent 将回复返回给用户
7. **用户反馈**：用户可评价，评价数据用于后续优化

若置信度低于阈值（如 0.4），则：
1. Agent 调用 `create_gov_work_order` 工具创建工单
2. 工单状态变为 `UNASSIGNED`
3. 进入人工办理流程

## 8. 总结

本系统以 **Spring AI MCP Server** 为核心，通过动态工具注册机制和 Dubbo 泛化调用，实现了 Agent 对后端政务服务的标准化调用。核心特点：

1. **零侵入调用**：通过 Dubbo Generic Service，无需引入业务 Jar 包
2. **动态配置**：工具定义存储在 Nacos，支持热更新
3. **策略扩展**：通过策略模式支持 LOCAL、DUBBO、REMOTE 三种调用方式
4. **规范枚举**：前后端共享工单状态、操作等枚举定义，确保数据一致性

该方案可作为 MultiAgent 系统开发的参考实现。
